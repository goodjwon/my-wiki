# Local-first + Append-only + 파생값

## 정의

세 가지 결정이 한 묶음입니다.

| 결정 | 내용 |
|------|------|
| **Local-first** | 모든 읽기·쓰기는 기기 안 DB에서 즉시 끝난다. 네트워크·동기화·외부 연동은 전부 백그라운드이고, 실패해도 앱은 완전 동작한다 |
| **Append-only** | 기록은 추가만 한다. 수정은 없고, 삭제는 삭제 시각을 표시하는 tombstone으로 남긴다 |
| **파생값은 계산** | 스트릭·진행률·뱃지·통계는 저장하지 않는다. 필요할 때 기록에서 다시 계산한다 |

> 핵심 인사이트: 정합성 버그의 대부분은 "같은 사실을 두 곳에 저장"할 때 생깁니다. 저장하는 곳을 하나(기록)로 줄이면 파생값은 항상 재현 가능하고, "언제 다시 계산하나"라는 질문 자체가 사라집니다.

[[entity-workout-history]]의 설계 원칙 1·2를 개념으로 분리한 페이지입니다.

## 왜 Local-first인가

요구사항 1번이 "3초 안에 기록"이었습니다. 네트워크 왕복 하나가 들어가는 순간 이 요구는 깨집니다. 그래서 순서를 뒤집었습니다 — 로컬이 진실이고, 서버·동기화는 있어도 나중에 뒤에서 따라옵니다.

| 얻은 것 | 잃은 것 |
|---------|---------|
| 계정·로그인·서버 비용 0 | 기기 간 동기화는 별도 마일스톤으로 |
| 비행기 모드에서 완전 동작 | 앱 삭제 = 데이터 삭제 (사용자에게 명시) |
| 스토어 개인정보 설문 "수집 없음"이 사실 | 백업·복원을 따로 설계해야 함 |
| 저장 지연이 항상 로컬 DB 쓰기 시간뿐 | 서버 기반 기능(랭킹·푸시) 포기 — 의도한 Non-goal |

## Append-only가 만드는 것

| 상황 | 수정 가능 모델 | Append-only 모델 |
|------|--------------|-----------------|
| 사용자가 저장 직후 실수를 되돌림 | 행 UPDATE 또는 DELETE | tombstone 표시 (5초 실행취소 스낵바) |
| 통계에서 삭제된 기록 처리 | 이미 사라져 재현 불가 | 삭제 시각 기준으로 필터, 언제든 재현 |
| 워치·헬스 등 여러 출처의 기록 병합 | 충돌 해결 로직 필요 | ID가 다르면 전부 추가, 같으면 무시(멱등) |
| 뱃지 회수 여부 | 회수 로직 필요 | 회수하지 않음 — 획득도 추가 전용 |

스키마 변경도 같은 철학입니다. 컬럼은 추가만 허용하고 삭제·타입 변경은 금지, 신규 컬럼은 기본값 또는 NULL 허용 — 구버전 데이터가 항상 읽힙니다.

## 파생값을 저장하지 않으면 느리지 않은가

느려질 수 있습니다. 그때 순서가 중요합니다.

1. **윈도우 캡을 먼저** — 스트릭 조회는 400일 상한. 뱃지 판정은 무손실(400일 스트릭 뱃지가 최대), 표시 수치만 캡됩니다.
2. **성능 테스트로 상한을 잠금** — 조회 50ms 상한을 테스트에 박아 회귀를 막습니다.
3. **캐시는 마지막** — rollup 캐시는 동기화 마일스톤에서 재평가. 캐시를 먼저 두면 "캐시 무효화 시점"이라는 새 문제가 생깁니다.

실시간성은 두 개의 틱 스트림으로 해결합니다.

| 틱 | 발화 조건 | 갱신 대상 |
|----|----------|----------|
| 테이블 변경 틱 | 기록 테이블에 insert/update가 일어날 때 | 오늘 누적·목표 진행·히트맵·히스토리 |
| 자정 틱 | 로컬 자정 +1초(체인 예약) | 오늘 누적·목표 진행·스트릭 |

파생값 Provider가 이 두 스트림을 watch하면, 저장 경로에서 일일이 무효화를 호출하지 않아도 됩니다(즉시성 보장용 명시 무효화는 병행).

## 함정 1 — "하루"의 경계

저장 타임스탬프는 epoch ms UTC입니다. 그런데 "오늘 했는가", "연속 며칠인가"는 **기기 로컬 자정** 기준입니다. 두 기준이 섞이는 순간 스트릭이 하루 어긋납니다.

| 잘못된 판정 | 결과 |
|------------|------|
| UTC 날짜로 "오늘" 판정 | 한국 오전 8시 이전 기록이 어제로 집계 |
| 저장 시점 타임존을 기록에 박음 | 여행 중 기록이 귀국 후 다른 날로 이동 |
| 자정 넘김을 화면이 모름 | 00:00 이후에도 어제 누적이 "오늘"로 표시 |

지키는 방법은 두 가지입니다. 시계를 주입(clock zone)해 테스트에서 자정·타임존을 고정하고, 시계 seam은 앱에 **하나만** 둡니다(여러 Provider가 각자 now를 부르면 계통이 갈라집니다).

## 함정 2 — 증분 가져오기의 앵커

외부 소스(헬스 앱)에서 기록을 증분으로 가져올 때 "마지막으로 가져온 시각" 앵커를 둡니다. 여기서 사고가 났습니다.

```text
배치 실행 → 권한이 어중간해 샘플 전부 skip → imported = 0
그런데 앵커는 "배치가 돌았으니" 전진
→ 다음 배치부터 그 이전 기록은 영영 대상 밖 → 이후 0건
```

교훈은 한 줄입니다. **앵커는 실제로 가져온 것이 있을 때만 전진시킨다.** 전체 가져오기는 연 단위 청크(최신→과거)로 나누고, 청크 중간 실패는 불완전 플래그로 부분 성공을 보존해 전체 재스캔이 반복되지 않게 합니다.
