## 2. 확정 정책 (2026-07-03 사용자 결정)

1. **Spring 실습 = 자족형(self-contained)** — ch06 6.1에서 start.spring.io로 만드는 `demo` 프로젝트를 Spring 챕터의 공식 실습 프로젝트로 승격. `day_by_spring`은 "참고: 실제 프로젝트에서는" 격으로만 언급(private 저장소라 학습자 접근 불가). 저장소를 나중에 공개하면 클론 URL 한 줄 추가로 전환 가능.
2. **ch07 Querydsl 실습 가능화** — 의존성·Q타입 생성·엔티티까지 갖춘 "Querydsl 실습 환경 만들기" 절을 신설하고 완결 클래스 7개에 스캐폴드 부착. `LoanRepository` 이중 정의 통합.
3. **ch03 전면 실행형화** — 절마다 스니펫들을 주제별 Demo 클래스로 묶어 실행 가능하게 재구성(기존 "예상 결과"와 정합). 비교용 2~3줄 발췌는 스니펫으로 유지.
4. **Core(ch01~05) 실습 = ch01 1.2 프로젝트 승계** — 챕터별 패키지 `com.example.chNN`.

## 3. §7-7 실습 스캐폴드 표준 (authoring-standards에 넣을 내용)

**구분**: 모든 코드블록은 **스니펫**(발췌·비교·퀴즈 — 스캐폴드 불필요) 또는 **실습 예제**(파일로 만들어 실행하는 단위 — 4요소 필수) 둘 중 하나. 완결 클래스 외형인데 실습용이 아니면 "참고 코드" 라벨로 구분.

**실습 예제 4요소**:

1. **파일 리드인** — 코드블록 바로 위: `**파일**: src/main/java/com/example/ch02/AnimalDemo.java`
2. **package 선언** — 코드 첫 줄, 리드인 경로와 일치
3. **한 블록 = 한 파일** — 파일명 = public 클래스명. 보조 클래스는 non-public으로 같은 파일 허용, public 여러 개면 블록 분리
4. **실행 명령 + 예상 결과** — 예제(묶음) 끝에 bash 실행 명령 + `예상 결과` 펜스

**챕터 → 프로젝트 매핑**:

| 챕터 | 기준 프로젝트 | 패키지 |
|------|-------------|--------|
| ch01~05, ch09 §9.2 | ch01 1.2에서 만든 Maven/Gradle 프로젝트 | `com.example.chNN` |
| ch05 소켓·JDBC | 단일 파일 javac 병행 허용 (작업 디렉터리 명시) | default 허용 |
| ch06~08·10 (Spring) | ch06 6.1 start.spring.io `demo` (자족형) | `com.example.demo.*` |
| ch11 미니프로젝트 | 예제별 자체 프로젝트 (트리 제시, §11.23 모델) | 예제 자체 규칙 |

**클래스명 규칙**: 챕터 내 고유. 드라이버 클래스 `Main` 금지 → `<주제>Demo`. 실행 명령 표준형: 프로젝트는 Maven 우선(`./mvnw compile exec:java -Dexec.mainClass=...` 또는 테스트는 `./mvnw test -Dtest=...`) + Gradle 대안, 단일 파일은 `javac`/`java`.

## 4. 실행 구조

```
Phase A  정책 확정 (완료 — §2)
Phase B  §7-7 명문화 + scripts/scaffold-lint.sh 신작 + 캘리브레이션    ← 프롬프트 A
Phase C  챕터별 배치 적용 (3병렬 × 3배치 + 대형 단독)                  ← 프롬프트 B
         배치1: ch02 · ch04 · ch09      (스캐폴드 부착 중심)
         배치2: ch01 · ch06 · ch11      (프로젝트 연결·실행 명령 보강)
         배치3: ch05 (버그 수정+대량 부착) · ch03 (전면 실행형화) · ch07 (실습 환경 신설)  ← 대형, 사이클 5회
         ch08·ch10: 프로젝트 전제 문구 정리만 (day_by_spring → 자족형/참고 격하)
Phase D  컴파일 스모크 검증 + 적대적 검수 + 배포                        ← 프롬프트 C·D
```

종료 조건 3종: goal(scaffold-lint 0건 + 스모크 통과) / resource(파일당 3~5사이클) / budget(동시 3파일).

## 5. 업무지시 프롬프트

### 프롬프트 A — 시스템 구축 (1회)

````text
§7-7 실습 스캐폴드 표준을 명문화하고 검증 게이트를 만든다.

1) wiki/guide-wiki-authoring-standards.md에 "### 7-7. 실습 스캐폴드 (코드 예제)" 신설 —
   내용은 wiki/plan-practice-scaffold.md §3을 그대로 옮긴다 (구분 원칙·4요소·프로젝트
   매핑 표·클래스명 규칙·실행 명령 표준형).
2) scripts/scaffold-lint.sh 작성 — 인자로 받은 파일에서 기계 검출 가능한 위반만 검사,
   위반 시 exit 1 + 목록 출력:
   ① `**파일**:` 리드인의 경로에서 (패키지 경로, 파일명)을 추출해 바로 다음 java 펜스의
      package 선언·public 클래스명과 대조 (불일치=위반)
   ② java 펜스 안에 public 최상위 타입(class/interface/enum/record)이 2개 이상이면 위반
   ③ 드라이버 검출: `public static void main`이 있는 클래스명이 `Main`이면 위반
   ④ 리드인 없는 완결 예제 검출은 휴리스틱 한계로 제외 (사람/검수 에이전트 몫)
3) 캘리브레이션: 모범(ch11 §11.23 블로그 구간)에 돌려 오탐 확인, 기지 위반(ch02 Main 19회,
   ch05 L1830 파일명 불일치)에 돌려 검출 확인. 오탐 나면 스크립트 수정 후 재검증.
4) CLAUDE.md 셀프 체크에 "실습 예제 있는 페이지: scaffold-lint 통과" 1줄 추가.
완료 기준: §7-7 존재 + 캘리브레이션 통과 + build-site.sh 통과. 커밋 1개.
````

### 프롬프트 B — 챕터 정합 루프 (챕터당 1회)

````text

   유지 영역: 기존 코드 로직(스캐폴드 외 코드 내용 변경 금지 — package 추가·개명은 허용),
````

### 프롬프트 C — 컴파일 스모크 검증 (Phase C 후 1회)


### 프롬프트 D — 적대적 검수 (전체 완료 후 1회)

