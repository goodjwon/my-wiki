# 얇은 워치 클라이언트

## 정의

폰과 워치 두 기기가 있을 때, **진실(source of truth)은 폰 DB 하나**로 두고 워치는 두 가지만 가지는 설계입니다.

| 워치가 가진 것 | 내용 |
|--------------|------|
| 스냅샷 캐시 | 폰이 밀어준 "오늘 종목·목표·누적" 읽기 전용 사본 |
| 미전송 큐 | 워치에서 만든 기록 중 아직 폰이 받았다고 확인하지 않은 것 |

> 핵심 인사이트: 워치에 DB를 두는 순간 "두 DB의 충돌 해결"이 필요해집니다. 그건 동기화 마일스톤의 일이지 워치 앱의 일이 아닙니다. 워치는 캐시 + 큐로 충분합니다.

[[entity-workout-history]]의 설계 원칙 4입니다.

## 메시지 흐름

| 방향 | 언제 | 무엇 |
|------|------|------|
| 폰 → 워치 | 기록 저장·목표 변경·종목 변경 등 트리거 5종, 2초 디바운스 | 스냅샷 전체(작음 — 오늘 것만) |
| 워치 → 폰 | 워치에서 기록 생성 즉시 | 기록 1건(ID·종목·수량·시각) |
| 워치 → 폰 | 연결 복구 시 | 스냅샷 재요청 |

폰과 워치는 공통 JSON 메시지 스키마를 씁니다. Apple Watch(WatchConnectivity)와 Wear OS(Data Layer)가 전송층만 다르고 메시지는 같습니다.

## 멱등 수신 — 재전송이 안전해지는 열쇠

워치는 기록 ID를 **자기가** UUIDv7로 만들어 보냅니다. 폰은 같은 ID가 두 번 오면 무시합니다.

| 상황 | 멱등 수신 없이 | 멱등 수신으로 |
|------|-------------|-------------|
| 즉시 전송 성공, 응답 유실 → 큐에서 재전송 | 기록 2건 | 1건 |
| 워치가 재부팅되어 큐를 다시 flush | 중복 | 무해 |
| 폰·워치 양쪽에서 같은 기록 표시 | 어느 쪽이 진짜인지 불명 | ID가 같으니 같은 것 |

UUIDv7은 시간순 정렬이 가능해 기록 시각과 ID 순서가 일치합니다. [[concept-local-first-append-only]]의 append-only와 맞물려 "추가 아니면 무시" 두 동작만 남습니다.

## 전송 전략 — 즉시 + 큐 폴백 + 낙관적 에코

| 단계 | 동작 | 이유 |
|------|------|------|
| 1 | 즉시 메시지 전송 시도 | 폰이 깨어 있으면 1초 안에 반영 |
| 2 | 실패하면 큐에 넣고 백그라운드 전송 | 폰이 멀거나 잠겨 있어도 유실 없음 |
| 3 | 워치 화면은 로컬에 즉시 반영(낙관적 에코) | 사용자는 전송 여부를 기다리지 않음 |

실기기 검증에서 나온 피드백 6건 중 3건이 이 층이었습니다 — 탭 지연(제스처 배타 처리), 화면 이탈 시 부분 카운트 유실, 전송 즉시성. 시뮬레이터에서는 하나도 재현되지 않았습니다.

## 워치 UI 원칙 — 폰과 같은 문법

| 폰 | 워치 |
|----|------|
| 카드 탭 → 카운트 화면 | 종목 선택 → 탭 카운트 |
| 화면 탭 = +1 | 화면 탭 = +1, 크라운으로 조정 |
| 목표 도달 시 자동 저장 | 동일 |
| 오렌지=운동, 아쿠아=휴식 | 동일 색·햅틱 의미 |

거리형(달리기)은 워치 기본 운동 앱에 위임합니다 — 그 기록은 폰이 헬스 앱에서 가져옵니다. 워치 앱이 잘하는 것(탭 카운트)만 합니다.

## 삽질 로그

| 문제 | 해법 |
|------|------|
| 시뮬레이터에서 폰↔워치 세션이 붙지 않음 | 워치 앱에 시뮬레이터 전용 데모 스냅샷을 내장해 스토어 스크린샷 촬영 |
| 실기기 설치가 굳음 | 폰 Watch 앱 설치와 CLI 설치를 동시에 하지 않음. 워치 재부팅 직후 1분이 터널 골든타임 |
| 무료 팀 7일 서명 만료 | 유료 개발자 등록(1년 프로비저닝)으로 종료 |
| flavor(dev/staging/prod)별 companion 번들 불일치 | 9종(flavor × Debug/Release/Profile) 명시 매칭 |

## 같은 인사이트 패턴 — "진실은 하나, 나머지는 멱등"

| 페이지 | 진실의 위치 | 나머지가 하는 일 |
|--------|-----------|---------------|
| **이 페이지** | 폰 DB | 워치 = 캐시 + 큐, 폰은 ID로 멱등 수신 |
| [[concept-domain-event-eventual-consistency]] | 발행 애그리거트 | 소비자는 이벤트를 멱등하게 처리, 재전송 허용 |
| [[concept-id-reference-vs-object-reference]] | 각 애그리거트 | 경계 밖은 ID로만 참조 |
| [[concept-aggregate-boundary]] | 애그리거트 루트 | 경계 안에서만 불변식 보장 |
