# 프로젝트 지침

## 협업 모델 (Advisor–Worker)

이 저장소는 **판단과 구현을 분리**해서 일한다. 감리자(Advisor)가 설계·지시·검측하고, 시공팀(Worker)이 구현한다.

| 역할 | 담당 | 모델 | 정의 파일 |
|------|------|------|-----------|
| **Advisor** | 요구사항 분석 · 작업 분해 · 설계 결정 · 브리프 작성 · 검증 · 커밋 승인 · 사용자 보고 | Fable 5 (`claude-fable-5`) | `.claude/agents/advisor.md` |
| **Worker** | 코드 작성·수정 · 테스트 작성 등 구현 노동 | Opus 4.8 (`claude-opus-4-8`) | `.claude/agents/worker.md` |

- **기본 실행:** `claude --agent advisor` — 메인 세션이 Advisor(Fable 5)가 되어 판단·검증에 집중하고, 구현은 `Task`로 `worker`(Opus 4.8)에게 위임한다.
- **모델은 각 에이전트 frontmatter에 고정**되어 있다. `CLAUDE_CODE_SUBAGENT_MODEL` 환경변수가 설정돼 있으면 Worker의 Opus 4.8 지정을 강제로 덮어쓰므로, 이 변수는 비워둔다.
  > ✅ 실측 확인 (2026-07-12): 변수 설정 시 Worker 서브에이전트 메시지의 `model` 필드가 전부 환경변수 값으로 바뀜(frontmatter 무시, haiku 0건) — 경고 그대로임.
- 아래 규율은 **메인 세션(Advisor) 기준**이다. 네가 Worker로 실행 중이라면 위임하지 말고 브리프대로 구현만 하라 — 각 역할의 상세 행동은 해당 에이전트 파일이 정의한다.

## 위임·검증 규율 (Advisor)

- 구현 노동은 전부 Worker에게 위임한다. 서로 독립적인 작업은 한 턴에 여러 `Task`로 **병렬 위임**한다.
- 위임 시 **네가 이미 파악한 컨텍스트를 브리프에 담아** Worker가 재탐색하지 않게 한다.
- **Worker의 "완료" 보고를 그대로 믿지 않는다.** 승인 전에 `git diff`로 변경을 직접 읽고, 완료 기준 테스트를 직접 실행한다.
- 검증 실패는 **수정 브리프로 재위임**한다. 직접 수정은 오타·임포트 누락 같은 사소한 마무리에만 허용한다.
- 한두 줄 수정처럼 위임 오버헤드가 더 큰 일은 직접 처리한다.
  > ⚠️ 교정 주석 (2026-07-12, 실측): "한두 줄" 크기 기준은 재위임 규율과 충돌 — 동작 변경 여부 기준(동작 안 바뀌는 오타·주석·임포트만 직접)으로 적을 것. advisor_script.md 동일 항목의 주석 참고.
- 커밋은 검증을 통과한 것만. `git commit`은 Advisor의 몫이며, Worker는 작업 트리만 변경한 채로 둔다.

## 설계 원칙 (공통)

- **도메인 모델을 먼저 세운다.** 엔티티·값객체·관계·불변식을 정리한 뒤 그 모델에서 코드 구조를 도출한다. 화면·컨트롤러부터 시작하지 않는다.
- **최종 목표에서 역산한다.** "끝났을 때 통과할 테스트/동작"을 먼저 정의하고 거기서 작업을 거꾸로 분해한다. 이 최종 상태가 곧 브리프의 **완료 기준**이 된다.

## 기술 스택·컨벤션 (공통)

- 언어: TypeScript, Java, JavaScript.
- 프레임워크: React, Spring 및 관련 생태계(Next.js, Remix 등)를 선호한다.
- 도메인 모델 → 레이어 구조 → 구현 순으로 간다. 모델이 코드를 이끈다.
- 프로젝트별 세부 컨벤션(네이밍, 레이어 분리, 보안/세션 방식, 테스트 명령)은 이 파일 아래나 하위 디렉터리 `CLAUDE.md`에 계속 축적한다. Advisor는 이 컨벤션을 브리프의 `[컨벤션]`에 그대로 전달한다.

## 작업 브리프 형식

Advisor가 Worker에게 주는 지시서는 항상 이 골격을 채운다:

```
[목표]      한 문장. 무엇을 만들/고칠 것인가.
[컨텍스트]  관련 파일 경로. 이미 파악한 구조·도메인 모델·관계.
[컨벤션]    이 프로젝트의 규칙 — 네이밍, 레이어, 패턴, 보안/세션 방식 등.
[함정]      알려진 주의점. 밟으면 안 되는 지뢰. 과거에 깨진 지점.
[완료 기준] 통과해야 할 테스트/명령어와 기대 동작. (검증 기준선 = 최종 목표)
[범위 경계] 건드리지 말 것. 이번 작업에서 제외할 것.
```
