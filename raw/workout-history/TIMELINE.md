## 흔들리지 않은 설계 원칙 (ARCHITECTURE 2장)

1. **Local-first** — 모든 읽기/쓰기는 로컬 SQLite 즉시, 클라우드 없이 완전 동작
2. **Append-only + 파생값** — 기록 수정 금지, 통계·스트릭은 저장 않고 계산
3. **단일 TimerEngine** — 세트 휴식·루틴 인터벌·런 타이머가 한 상태기계 공유, 벽시계 기준
4. **워치는 얇은 클라이언트** — 진실은 폰 DB, 워치는 스냅샷 캐시 + 미전송 큐
5. **성능 예산** — 콜드 스타트 <1.5s, 기록 저장 <100ms (위반은 리뷰 블로커)
6. **기록은 행위의 산물** — 카운트·타이머·센서·헬스 가져오기가 기록을 만든다

## 삽질 로그 (다음에 안 밟기 위한 기록)

- **시뮬레이터 워치 WCSession은 안 붙는다** — 수차례 실패. 최종 해법은 워치 앱에
  시뮬 전용 데모 스냅샷 내장(`STORE_DEMO` env) → Ultra 3 시뮬 네이티브 422×514 캡처
- **워치 실기기 설치 굳음** — 폰 Watch 앱 설치와 CLI 설치를 동시에 하면 서로 끊어먹음.
  워치 재부팅 직후 ~1분이 터널 골든타임
- **무료 팀 7일 서명 만료 루프** — 유료 등록(1년 프로비저닝)으로 종료
- **ASC 업로드 반려 2건** — ① iPad 멀티태스킹 방향 요건 → iPhone 전용 지정으로 회피
  ② health 플러그인이 쓰기 API 참조 → 미사용이어도 NSHealthUpdateUsageDescription 필수
- **ASC 필드 제약** — 프로모션 텍스트에 `→` 문자 거부
- **제출 게이트 복병** — 개인정보 처리방침 URL + "수집 없음" 설문은 **게시(Publish)**까지
  해야 심사 추가 가능
- **번들 ID 교체의 대가** — 새 컨테이너라 기존 실기록 유실 → 헬스 가져오기로 복구 예정(B-67)
- **xcodebuild 산출물 경로 함정** — DerivedData에 떨어지는데 `build/ios/`의 구 flutter build
  잔해를 설치해 "왜 안 바뀌지" 삽질
