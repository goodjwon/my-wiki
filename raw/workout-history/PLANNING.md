# 운동 기록 앱 기획서 (Workout History)

작성일: 2026-07-19 · 상태: 초안 v0.3 (세트 모드 · 뱃지 보상 체계 · 달리기 지원 추가)

---

## 1. 제품 개요

**한 줄 정의**: "3초 안에 기록하는" 맨손운동 중심의 크로스플랫폼 운동 기록 앱 — 달리기 등 유산소도 같은 방식으로 가볍게 담는다.

핵심 가치:
- **빠른 기록** — 앱을 열고 3초 안에 세트 기록 완료. 타이핑 최소화, 탭 위주 UX.
- **목표와 달성의 분리** — 목표 설정은 폰에서 차분하게, 달성 체크는 폰/워치 어디서든 즉시.
- **코칭** — 인터벌 타이머와 "시작 / 쉬어라" 음성·햅틱 안내로 운동 중 화면을 볼 필요 없게.

## 3. 타겟 사용자 & 시나리오

- **주 사용자**: 집·사무실에서 맨손운동(팔굽혀펴기, 스쿼트, 플랭크 등)을 꾸준히 하려는 사람.
- **시나리오 A (수행 기록 — 2026-08-05 전면 개정, 사용자 "이미 했어요 삭제")**: 카드 탭 → [▶ 카운트 시작] → 한 개마다 탭(또는 자동 카운트 B-45) → 목표 도달 시 **자동 저장**. 사후 수동 저장 버튼은 없다 — "기록은 행위의 산물"(5장) 완전 적용. 방치 시 "했나요?" [했음]이 확인 통로, 앱 밖 운동은 헬스 가져오기(R11)가 흡수. *구 시나리오(사후 3초 기록)는 폐기.*
- **시나리오 B (워치 기록)**: 폰 없이 스쿼트 후 워치에서 종목 선택 → 디지털 크라운/버튼으로 횟수 조정 → 완료. 폰과 자동 동기화.
- **시나리오 C (인터벌 코칭)**: "팔굽혀펴기 15개 × 5세트, 세트 간 90초 휴식" 루틴 시작 → 워치가 진동과 음성으로 "시작!" / "쉬세요, 90초" 안내.
- **시나리오 D (목표)**: 폰에서 "주 5일, 하루 팔굽혀펴기 100개" 목표 설정 → 매일 달성률이 링/바로 표시, 달성 시 폰·워치 모두에서 축하 알림.
- **시나리오 E (세트 모드)**: 홈에서 팔굽혀펴기 카드 길게 누르기 → "세트 모드" 선택 → 15개 기록 → 휴식 타이머 90초 자동 시작(햅틱 안내) → 다음 세트 15개 프리필 → 4세트 후 "세트 종료" → 총 60개가 세트 내역과 함께 저장.
- **시나리오 F (뱃지)**: 7일 연속 목표 달성 순간 폰·워치에 "🔥 7일 스트릭" 뱃지 획득 알림 → 통계 탭 뱃지 컬렉션에서 다음 뱃지(14일)까지 진행률 확인.
- **시나리오 G (달리기)**: 달리기 카드 탭 → "런 타이머 시작" → 폰 주머니에 넣고 달리기 → 종료 탭 → 시간은 자동 입력, 거리 3.0km만 스테퍼로 입력 → 페이스 6'14"/km 자동 계산 후 저장. 나이키런으로 뛴 날은 헬스 연동으로 자동 합산되어 목표·스트릭이 채워짐.

## 4. 기술 스택 (제안)

### 결론: **Flutter(폰) + 네이티브 워치 앱(SwiftUI / Compose for Wear OS)**

| 후보 | 장점 | 단점 |
|------|------|------|
| **Flutter + 네이티브 워치** ✅ | 폰 코드 1벌, 성능·시작속도 우수, 커뮤니티 큼 | watchOS는 Flutter 미지원 → 워치는 네이티브 필요 |
| Kotlin Multiplatform (KMP) | 로직 공유 + 4개 플랫폼 전부 네이티브 UI | UI를 플랫폼별로 작성(iOS SwiftUI, Android Compose, 워치 2벌) → 초기 비용 큼 |
| React Native | 생태계 큼 | 워치 미지원은 동일, 콜드 스타트·성능이 Flutter 대비 불리 |

- 워치 앱은 어차피 네이티브가 필요(watchOS는 Swift 강제)하므로, 폰만이라도 1벌로 줄이는 Flutter가 현실적.
- 워치 앱은 **기록·타이머·목표 체크만 하는 경량 앱**으로 범위를 좁혀 유지비를 낮춘다.
- 대안: 개발 인력이 1인이고 iOS 우선이라면 "SwiftUI(iOS+watchOS) 먼저 → Android는 2단계" 전략도 가능.

### 데이터 계층 — Local-first (R1의 핵심)

- **로컬 DB**: SQLite(Drift) — 모든 읽기/쓰기는 로컬에서 즉시 완료. 네트워크 대기 없음.
- **클라우드 동기화**: Supabase(또는 Firebase) — 백그라운드 비동기 동기화, 기기 간 병합.
- **폰 ↔ 워치**: iOS `WatchConnectivity`, Android `Wearable Data Layer API`. 워치는 오프라인 기록 후 큐잉 → 연결 시 폰으로 전송.
- **충돌 해결**: 기록은 append-only 이벤트(삭제는 tombstone)라 충돌이 거의 없음. 목표 수정은 last-write-wins.
- 헬스 연동(선택): HealthKit / Health Connect에 운동 세션 기록 쓰기 + **러닝 워크아웃 읽어오기(R11)**.

## 5. 핵심 기능 정의

> **제품 원칙 — "기록은 행위의 산물" (2026-08-02 사용자 확정)**: 결과는 보여주는 것이고, 기록을 만들려면 운동별로 **적절한 수행 행위**가 있어야 한다 — 횟수형=탭 카운트(수행 화면·자동 카운트 B-45), 시간형=타이머, 거리형=런 타이머+센서 자동 수집(B-50)·헬스 가져오기(R11). 행위가 만든 값(타이머 시간·센서 거리/걸음수)은 결과에서 **읽기 전용** — 임의 수정은 기록 무결성 훼손. 수동 입력은 행위가 불가능한 상황의 **보정 fallback으로만** 유지한다(트레드밀·센서 미수집 — local-first: 헬스 없이도 완전 동작). **08-05 강화(사용자 원문)**: "운동앱이 연결 안 될 때만 쓰는 건데, 입력을 임의로 하는 것은 반칙" — 수행 화면의 사후 수동 저장 버튼을 전부 제거, 저장 트리거는 수행 완료(자동)·부분 기록·"했나요?" [했음]·헬스 가져오기 4개뿐. 앱 전역 설계 원칙 6으로 격상(ARCHITECTURE 2장·CLAUDE.md).

### 5.1 운동 종목 관리 (R6)
- 기본 제공 프리셋: 팔굽혀펴기, 스쿼트, 플랭크, 런지, 버피, 턱걸이, 크런치, 달리기(거리형)…
  - **시드 정책(2026-07-20 확정 · 2026-07-21 개정 · 2026-08-02 걷기 추가 — B-46 ① 사용자)**: 첫 실행 시 **대표 5종을 시드한다 — 팔굽혀펴기(횟수)·스쿼트(횟수)·플랭크(시간)·달리기(거리)·걷기(거리)** (걷기는 기존 설치에도 소급 — backfillSeedPresets, 승격 키 한정·tombstone 존중) (사용자 피드백: 처음부터 전 종목이 깔릴 필요 없음. 단위 유형별 대표 1개로 첫 기록 3초 원칙은 유지). 나머지 프리셋(런지·버피·턱걸이·크런치)은 종목 추가 > 프리셋 탭에서 원탭 추가. 시드는 기기 언어(ko 우선·미지원은 ko fallback)의 실제 문자열로 1회만(이름은 사용자 데이터라 l10n 키가 아님), 멱등 — **사용자가 프리셋을 전부 삭제한 뒤 재실행해도 되살아나지 않는다**(tombstone이 남아 "빈 상태"로 오인하지 않음).
- 사용자 정의 종목 생성: 이름, 아이콘/이모지, 색상, **기록 단위 유형** 선택
  - `횟수형` (팔굽혀펴기 20회), `시간형` (플랭크 60초), `횟수×무게형` (덤벨컬 10kg×12), `거리형` (러닝 3km)
- 종목별 기본값: 기본 횟수, 증가 단위(±1, ±5), 세트 간 기본 휴식 시간, **단위당 소요 시간(초/개 — 수행 화면 프롬프트·루틴 예상 시간용, 2026-07-22 추가)**.
- 자주 쓰는 종목은 홈에 고정(핀), 정렬은 최근 사용순.
- **종목 추가 진입점**: 홈 그리드 마지막 "＋ 종목 추가" 카드, 설정 > 종목 관리. 프리셋에서 고르거나 처음부터 만들기 — 폰 전용 화면(워치 제외).

### 5.2 빠른 기록 (R4)
- 홈 = 종목 카드 그리드. **카드 탭 → 수행·기록 화면(프리필) → 화면 탭 = 저장** (2탭 유지).
  - **2026-07-22 개정**: 원탭 즉시 저장(구 구현·7장 IA "원탭" 표기)은 오탭 문제로 폐기.
    사후 기록·실시간 수행을 한 화면에서 처리 — 상세는 `docs/specs/SPEC_QUICK_LOG.md`(확정 대기).
- 카드 길게 누르기 → 스테퍼(±)로 값 조정 후 저장.
- 저장 시 햅틱 + 카드에 오늘 누적치 즉시 반영 — **목표가 있으면 목표 대비로 표시** (예: "60 / 100개 · 60%", 달성 시 오렌지. 2026-07-22 확정).
- 실행 취소(Undo) 스낵바 5초 제공 — 잘못 눌러도 부담 없게.
- 위젯(홈 스크린) / 워치 컴플리케이션에서 원탭 기록 진입.

### 5.2.1 세트 모드 (R8) — 루틴 없이도 세트 운동
- 기록 시트에서 **단발 / 세트** 전환. 세트 모드 선택 시:
  1. 횟수 조정 후 "세트 완료" 탭 → 세트 1 저장
  2. **휴식 타이머 자동 시작** (종목별 기본 휴식 시간, ±30초 조정 가능) — 휴식 종료 3초 전 카운트다운, 종료 시 햅틱+알림음 (음성 "시작!"은 M3 코칭에서 추가 — 2026-07-19 확정)
  3. 다음 세트에 직전 횟수 프리필 → 반복
  4. "세트 종료" 탭 → 전체가 하나의 세트 그룹으로 저장 (예: "팔굽혀펴기 15·15·12·10 = 총 52개, 4세트")
- 루틴과의 차이: 루틴은 미리 짠 계획 실행, 세트 모드는 **즉흥 세트 운동**. 내부적으로 같은 휴식 타이머·안내 엔진을 재사용.
- 워치에서도 동일하게 동작: 세트 완료 → 손목 햅틱으로 휴식 종료 안내.
- 홈 카드의 오늘 누적치는 세트 합산으로 표시, 히스토리에는 세트 내역 펼쳐보기 제공.

### 5.3 목표 (R5)

> **개념 모델 개정(2026-08-17 사용자 확정 — `CONCEPTS.md`가 진실)**: 목표 입력은
> **"매일 N + 하는 요일 + 세트 방식"** 하나로 통일한다. 주 단위 목표·전체 운동일수
> 목표는 **입력에서 제거** — 주간 합계(매일 N × 요일 수)와 운동일수(기록 있는 날
> 세기)는 파생값으로 표시한다. 기존 데이터·스키마·판정 엔진은 유지(append-only),
> 아래 본문 중 주기 선택·전체 운동일수 서술은 구현 개편(B-63) 전까지의 기존 동작 기록이다.
- **설정은 폰에서만**: 종목, 목표량, 주기(일/주), 요일 지정, 기간(무기한/종료일).
  - 예: "팔굽혀펴기 100개/일", "스쿼트 300개/주", "주 5일 운동".
- **달성 반영은 자동**: 기록이 쌓이면 목표 진행률이 자동 계산. 별도 체크 불필요.
- **목표량 단위(2026-07-21 확정)**: 목표량은 선택한 종목의 unit_type 단위를 그대로 따른다 — 횟수형=회, 시간형=초, 거리형=**km 표시**(저장은 m, DEVELOPMENT.md 단위 규칙 불변), 전체 운동일수=일. 속도·페이스 목표(예: "6'00"/km 이하로 달리기")는 **비범위** — 페이스는 저장하지 않는 파생값이며(append-only+파생값 원칙) 전문 러닝앱 영역이라 도입하지 않는다.
- 폰·워치 모두에서 진행 링/게이지 표시, 100% 도달 시 양쪽에 축하 알림 + 연속 달성(스트릭) 카운트.
- **스트릭 판정 정책 (2026-07-20 advisor 확정)**: ① 진행 중인 오늘/이번 주는 끊지 않는다 — 직전 완결 주기까지로 판정, 달성 시 현재 주기 포함. ② 요일 지정 목표의 비활성 요일은 제외(세지도 끊지도 않음) — 스트릭 수치는 달력일이 아닌 활성 요일 달성 횟수(뱃지 임계값도 동일 기준). ③ 최고(best) 스트릭은 끊겨도 유지(5.5 뱃지 정책과 정합). ④ weekly 목표는 월요일 시작 주 단위 연속 달성, 요일 지정은 daily 전용.
- **목표 리마인더(B-62 ④, 2026-08-16 사용자 확정)**: 미달성 목표를 지정 시각(기본 20:00)에 **로컬 알림**으로 독려 — 서버 푸시 아님(Non-goal 준수). 내용은 마지막 앱 사용 시점의 남은 양(백그라운드 계산 없음), 오늘 목표 전부 달성 시 취소. 기본 off, 설정에서 토글(켤 때만 알림 권한 요청). 홈 링은 요일 지정·기간으로 오늘 판정에서 빠진 목표가 있으면 "오늘 N개 · 전체 M개"로 표기한다(B-62 ①).
- 달성 히스토리: 캘린더 히트맵(잔디), 주/월 통계, 종목별 추이 그래프.

### 5.4 인터벌 & 코칭 (R7)
- **루틴 빌더**(폰): [운동 구간 → 휴식 구간] 블록을 쌓아 만든다.
  - 예: 팔굽혀펴기 15개 → 휴식 90초 → ×5세트 반복.
  - 구간 유형: 횟수 기반(사용자가 완료 탭), 시간 기반(자동 진행 — B-26), **거리 기반(2026-07-25 사용자 확정 — 루틴 속 달리기: 실행 화면이 경과를 카운트업하고 완료 탭 시 소요 시간까지 기록해 페이스 보존. 정밀 측정이 필요하면 단독 런 타이머)**.
- **실행은 폰·워치 양쪽**: 큰 타이머 + 현재/다음 구간 표시.
- 안내: 구간 전환 시 음성 TTS("시작!", "쉬세요"), 햅틱 패턴(시작=2번 강하게, 휴식=1번 길게), 휴식 종료 3초 전 카운트다운.
- 완료 시 루틴 전체가 기록으로 자동 저장.
- **루틴 ↔ 목표·통계 관계(2026-07-24 확정, A안)**: 루틴은 **기록을 만드는 수단**이다. 루틴 실행의 운동량은 `workout_records`로 저장되어 목표 진행률·통계·뱃지에 **자동 합산**되며, 루틴과 목표 사이에 직접 참조는 없다(`routine_session_id`는 출처 표시). 이 인과는 표현 계층에서 보여준다 — 통계 히스토리의 루틴 그룹 행(B-31), 루틴 카드의 완주 통계(B-32), 홈 오늘의 루틴(B-29). "루틴 N회" 목표 유형(B-33)은 비범위, 수요 확인 후 재검토.
- **목표 기반 루틴 빌더(B-62 ③, 2026-08-16 사용자 확정 — "목표가 재료, 루틴은 엮는 방법")**: 루틴 빌더는 내 daily 종목 목표를 가져와 세트로 분배(목표량 ÷ 종목 기본횟수, 나머지는 마지막 세트·휴식은 종목 기본값)해 블록을 만드는 것을 기본 흐름으로 한다. 백지 조립은 목표 없는 종목 추가용으로 유지. 데이터 참조는 여전히 없음 — 가져오기는 생성 시점 1회 변환(A안 유지). 완주 화면은 이번 세션의 목표 기여("목표 +30 → 90/100 · 달성!")를 표시한다(B-62 ②).

### 5.5 뱃지 · 보상 체계 (R9) — 스트릭 + 누적 마일스톤
- **스트릭 뱃지**: ~~연속 목표 달성~~ → **기록한 날 연속(운동일, 목표 무관 — 2026-07-24 개정, SPEC_REWARD_STORY 5장)** 3 · 7 · 14 · 30 · 60 · 100 · 365일. 스트릭이 끊겨도 획득한 뱃지는 유지. 스토리: "물 주기" 💧
- **누적 마일스톤 뱃지**: 종목별 누적량 기준 — 횟수형 100 · 500 · 1,000 · 5,000 · 10,000개, 시간형 1 · 10 · 50시간, 거리형 10 · 100 · 500km. 스토리: "등반" ⛰(베이스캠프→정상, SPEC_REWARD_STORY 5장 — 2026-07-24 혼합 컨셉 확정)
- **이벤트 뱃지**: 첫 기록, 첫 목표 달성, 첫 루틴 완주, 주 100% 달성, 새벽/심야 운동 등 소량의 재미 요소.
- **획득 순간**: 기록 저장 직후 폰·워치 양쪽에서 축하(풀스크린 컨페티 + 햅틱). 하루 여러 개 획득 시 묶어서 한 번만.
- **뱃지 컬렉션 화면**(통계 탭 내): 획득 뱃지는 컬러, 미획득은 실루엣 + **다음 뱃지까지 진행률 게이지** ("1,000개까지 240개 남음").
- 원칙: 뱃지는 격려 수단 — 미달성 압박 알림은 보내지 않는다. 레벨·포인트·랭킹은 도입하지 않음(단순함 유지).

### 5.6 달리기 · 유산소 (R10 · R11)

**우선순위 개정(2026-07-31 사용자 확정)**: 달리기의 **기본 경로는 헬스 연동 자동 가져오기**다 — 러너는 이미 가민·애플워치·나이키런 등으로 측정하고 그 결과가 건강앱(HealthKit/Health Connect)에 모인다. 수동 입력(기록 시트·런 타이머)은 **가져올 수 없을 때의 fallback**(헬스 미연동·권한 거부·기기 없이 뛴 날). 화면 우선순위도 이를 따른다: 헬스 연동이 켜져 있으면 달리기 카드에는 "자동으로 가져와요" 상태가 기본이고, 수동 입력은 보조 진입.

- **헬스 연동 가져오기(기본)**: HealthKit / Health Connect의 러닝 워크아웃을 읽어 '달리기' 종목 기록으로 자동 합산 → 목표·스트릭·마일스톤 뱃지에 반영.
- **거리형 기록 시트(fallback)**: 거리(0.5km 단위 스테퍼) + 시간 입력 → **페이스(분/km) 자동 계산**·표시. 마지막 기록값 프리필은 동일.
- **런 타이머(fallback, 수동 측정)**: 시작 탭 → 스톱워치 실행(폰·워치, 백그라운드 유지) → 종료 시 시간 자동 입력, 거리만 넣으면 저장. GPS 없이 배터리·권한 부담 zero.
  - 중복 방지: 외부 기록은 `externalSource + externalId`로 식별, 같은 세션 재가져오기 무시.
  - 종목별 자동 가져오기 on/off (설정 > 헬스 연동). 가져온 기록은 히스토리에 출처 아이콘 표시.
- **자동 수집(B-50, 2026-08-02 사용자 확정)**: 런 타이머 [종료] 시 타이머 구간의 헬스 센서 샘플(distanceWalkingRunning·stepCount)을 합산해 거리·걸음수를 결과에 자동 프리필 — 권한 거부·데이터 없음은 수동 입력 fallback. 정확도 부족 판단 시 '지도 없는 GPS 거리 측정'(B-47)으로 승격 재검토.
- **비범위(Non-goal)**: GPS 실시간 트래킹·경로 지도는 만들지 않는다 — 전문 러닝앱(나이키런·스트라바)과 경쟁하지 않고 연동으로 흡수. 걷기·자전거 등 다른 유산소도 같은 거리형+헬스 연동 패턴 재사용.

### 5.7 워치 앱 범위 (경량)
- 오늘 목표 링 확인, 빠른 기록(크라운/버튼 스테퍼), **세트 모드(휴식 햅틱 안내)**, **런 타이머(스톱워치)**, 루틴 실행(타이머+햅틱), 컴플리케이션, 뱃지 획득 축하 표시.
- 종목 생성·목표 설정·통계·뱃지 컬렉션은 워치에서 제외 → 폰으로 유도.

## 6. 데이터 모델 (초안)

```
Exercise            운동 종목
  id, name, emoji, color, unitType(reps|seconds|reps_weight|distance),
  defaultAmount, incrementStep, defaultRestSec, isPinned, sortOrder, deletedAt

WorkoutRecord       운동 기록 (append-only)
  id, exerciseId, amount, weight?, durationSec?, distanceM?,
  setGroupId?, setIndex?, restSecBefore?,       ← 세트 모드: 같은 setGroupId로 묶임
  recordedAt, source(phone|watch|widget|health),
  externalSource?, externalId?,                 ← 헬스 연동 가져오기 중복 방지

  ※ 거리형 페이스는 durationSec/distanceM에서 파생(저장 안 함)

Goal                목표
  id, exerciseId?(null=전체 운동일수 목표), targetAmount,
  period(daily|weekly), activeDays[Mon..Sun]?, startDate, endDate?, deletedAt

GoalProgress        (파생/캐시) 날짜별 달성률·스트릭 — 기록에서 계산

Routine             인터벌 루틴
  id, name, blocks[ {type(work|rest), exerciseId?, targetAmount?, durationSec?} ],
  repeatCount

RoutineSession      루틴 실행 이력
  id, routineId, startedAt, completedAt?, completedBlocks

BadgeDefinition     뱃지 정의 (앱 내장, 코드로 관리)
  id, type(streak|milestone|event), exerciseUnitType?, threshold, tier(bronze|silver|gold), icon, title

EarnedBadge         획득 뱃지 (append-only, 동기화 대상)

```

- 뱃지 판정은 기록 저장 시점에 로컬에서 계산(Local-first 유지) — 진행률은 기록·목표에서 파생.
